# Как здесь работать

## Язык

| Что | Язык |
|---|---|
| Код, комментарии, KDoc, имена тестов, сообщения исключений, `description` Gradle-задач | английский |
| Сообщения коммитов, названия PR | английский |
| Корневой `README.md` — витрина проекта | английский |
| `docs/`, `BACKLOG.md`, этот файл | русский |

Внутри русских документов идентификаторы, URL, имена переменных окружения и заголовки HTTP
пишутся вербатим как в коде.

**Почему так.** Репозиторий открытый: исходник и текст исключения читает кто угодно, а проектные
документы ведёт один человек. Правило заведено до первого коммита кода намеренно — переводить
постфактум дороже: правка задевает каждый файл и тонет в диффе.

Проверка перед PR:

```bash
grep -rnP '[\x{0400}-\x{04FF}]' --include='*.kt' --include='*.kts' --include='*.toml' --include='*.yaml' .
```

В тестовых данных кириллица законна (проверка октетов против символов) — такие места помечать
комментарием.

Якоря решений (`Р1`, `Р8`) в русском research'е дублируются латиницей при ссылке из кода:
`// see research D8`.

## Документация

Инвариант: **`main` описывает то, что есть.** Кода пока нет, поэтому документы слоёв стоят в
`status: draft`, а поведение помечено как целевое. Первый коммит, разошедшийся с документом,
правит документ **тем же PR**.

Второй инвариант: **проверенное отделяется от предполагаемого явно.** Факт в `docs/research/`
несёт указание, где он проверен (строка в статической библиотеке, файл в klib, листинг Maven
Central). Гипотеза называется гипотезой и имеет адрес проверки — «проверить в M2». Документ, не
отличающий одно от другого, вреднее отсутствия документа.

Меняешь утверждение — перепроверь **источник**, а не соседний документ.

Новый документ пишется по шаблону из `docs/templates/` и в том же коммите добавляется в список
в `docs/README.md`.

## Стиль кода

ktlint 1.8.0, версия зафиксирована в `gradle/libs.versions.toml`. Версии CLI и Gradle-плагина
обязаны совпадать.

```bash
~/.local/bin/ktlint -F "**/*.kt" "**/*.kts"
```

## Тесты

Общий код гоняется и на JVM, и на native: `:shared:jvmTest` и `:shared:macosArm64Test`. Расхождение
между ними — находка, а не флейк.

Отдельное требование к агенту: **компонент, который по замыслу глотает свои ошибки, обязан иметь
тест против настоящего ввода-вывода.** Фейк проверяет всё, кроме единственного, что у такого
компонента может сломаться незаметно. В соседнем проекте это стоило двух молчаливых поломок в
проде по несколько месяцев каждая.

Kotlin/Native запрещает запятые в именах тестов в бэктиках.
