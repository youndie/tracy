# CLAUDE.md

Guidance for working in this repository.

## Что это

**tracy** — логи Ktor-сервисов, сложенные так, чтобы их читал кодовый агент: KMP-плагин-агент
внутри целевого сервиса, нативный сервер с SQLite + FTS5, сквозной `traceparent` и MCP как
основной путь чтения. Подробности — [README.md](README.md).

**M0–M7 закрыты**, кроме трёх задач, которым нужен настоящий поток и выкатка (M-66, M-67, M-74).
Что делать дальше — [BACKLOG.md](BACKLOG.md).

Одно наблюдение из M7, которое стоит держать в голове при чтении галочек: 266 зелёных тестов не
показали, что **цикла доставки нет**, что `retention.enforce()` никто не вызывает и что канал
`suppressedKeys` не доезжает до агента. Все три компонента были написаны и покрыты тестами — и ни
у одного не было вызывающего. Тест проверяет функцию; что функцию кто-то зовёт, проверяет только
запуск.

`linuxX64Test` на macOS **`SKIPPED`** — эти тесты запускаются только на Linux. Прогон
`./gradlew build` на маке не означает, что зелены все нативные таргеты; для linux-таргетов нужна
linux-машина (адрес и способ подключения — в личных заметках, не здесь).

## С чего начинать сессию

1. [docs/research/research-architecture.md](docs/research/research-architecture.md) — решения и их
   обоснования. Без этого файла задачи выглядят как «сделай очевидное», а очевидное здесь часто
   неверно:
   * транспорт — **HTTP батчами, не UDP**, в отличие от metrik: потерянная строка `ERROR` — это
     ровно та строка, за которой пришли, и стектрейс не влезает в датаграмму;
   * **корреляция на Kotlin/Native не бесплатна**: `ThreadContextElement` JVM-only, MDC нет,
     trace id достаётся только из корутинного контекста;
   * **доверие к тексту лога определяется на записи, а не на чтении** — потому что в
     `"user 42 logged in"` уже не видно, откуда взялось `42`;
   * **спаны есть, но только на границах** (входящий запрос, исходящий вызов, ручной `withSpan`):
     автоинструментации библиотек нет и не будет, неинструментованное время показывается как
     неатрибутированное;
   * **хвостовое решение о семплировании вниз по цепочке не едет** — к моменту решения исходящие
     вызовы уже сделаны; для ошибок это и не нужно, они поднимаются вверх ответами.
2. [BACKLOG.md](BACKLOG.md) — что делать.
3. Документ слоя, к которому относится задача: `docs/features/`, `docs/api/`, `docs/services/`.

## Модули

| Модуль | Что это | Таргеты |
|---|---|---|
| `:shared` | модель записи, разбор `traceparent`, редакция — общий код агента и сервера | jvm, macosArm64, linuxX64, linuxArm64 |
| `:agent` | API логирования и Ktor-плагин, встраивается в целевой сервис | jvm, macosArm64, linuxX64, linuxArm64 |
| `:server` | приём, хранение, чтение, MCP; нативный бинарь | jvm (dev), macosArm64, linuxX64, linuxArm64 |

`jvm`-таргет сервера существует для локальной разработки и тестов; деплоится нативный бинарь.

## Команды

```bash
./gradlew build                        # всё: компиляция всех таргетов, ktlintCheck, тесты
./gradlew :server:macosArm64Test       # тесты сервера (native — единственный настоящий таргет)
./gradlew :shared:jvmTest              # быстрый прогон общего кода
./gradlew :agent:macosArm64Test        # агент на нативе
```

Полная сборка с нуля идёт минуты: `linuxX64`/`linuxArm64` на macOS кросс-компилируются. В обычном
цикле собирай конкретный модуль и таргет, а не `build`.

## Стиль кода

ktlint **1.8.0**, версия зафиксирована в `gradle/libs.versions.toml` и оттуда же подставляется в
Gradle-плагин. Версии CLI и плагина обязаны совпадать — иначе локальный формат и CI расходятся.

```bash
~/.local/bin/ktlint -F "**/*.kt" "**/*.kts"
```

## Язык

Код — **английский**: комментарии, KDoc, имена тестов, сообщения исключений, `description` задач
Gradle, сообщения коммитов, корневой `README.md`. Документация (`docs/`, `BACKLOG.md`,
`CONTRIBUTING.md`) — **русская**; идентификаторы, URL и заголовки HTTP внутри неё — вербатим как в
коде. Репозиторий открытый: исходник и текст исключения читает кто угодно, проектные документы
ведёт один человек. Проверка — `grep` по кириллице в `*.kt`/`*.kts`/`*.toml`/`*.yaml`.

Якоря решений в русских документах пишутся латиницей (`Р1` → в тексте `research §Р1`, в
английских комментариях — `research D1`), чтобы на них можно было ссылаться из кода.

## Правило, которое стоит соблюдать

> Проверяй по коду и артефактам, не пиши по памяти.

Каждый факт в `docs/research/` помечен тем, где он проверен: строка в статической библиотеке,
файл в klib, листинг Maven Central, документ соседнего проекта. Гипотезы названы гипотезами и
имеют адрес проверки («проверить в M2»). Меняешь утверждение — перепроверь источник, а не
соседний документ.

Отдельно: **сигнатуры MCP SDK смотреть в klib или dokka, а не в примерах на сайте** — сайт
отстаёт от версии, и примеры не компилируются.

## Правило про документацию

> **`main` описывает то, что есть.**

Документы слоёв стоят в `status: draft`, пока описанное ими поведение не написано целиком.
Коммит, разошедшийся с документом, правит **документ** тем же PR — так уже сделано трижды:
имя клиентского спана, пол семплирования, `getaddrinfo`.
