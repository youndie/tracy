# docs — документация tracy

**tracy** — логи Ktor-сервисов, сложенные так, чтобы их читал кодовый агент: плагин-агент внутри
сервиса, нативный сервер с SQLite + FTS5, сквозной `traceparent` и MCP как основной путь чтения.

Документация живёт внутри репозитория продукта и разложена по слоям: от «что и зачем» к «как это
устроено на проводе» и «как эксплуатируется».

```
[ Research — почему архитектура именно такая, что проверено, что гипотеза ]
                              │
[ Feature (что и зачем + BDD) ]
                              │
[ API / протокол (контракт на проводе) ]
                              │
[ Service (кто владеет, как деплоится) ]
```

| Слой | Папка | Отвечает на вопрос |
|---|---|---|
| Research | `research/` | почему архитектура именно такая; что проверено, что гипотеза |
| Feature | `features/` | что делает система и зачем, BDD-сценарии = критерии приёмки |
| API | `api/` | контракты: провод агент→сервер, HTTP чтения, MCP-инструменты |
| Service | `services/` | зона ответственности, конфиг, деплой, грабли |

Слоя `screens/` нет: клиента, который кто-то будет менять по документу, в MVP нет вовсе
(research §Р9). Когда UI появится, он опишется разделом в `services/tracy-server.md`.

## Оговорка про статус

Инвариант docs-подхода — **`main` описывает то, что есть**. Кода в репозитории пока нет, поэтому
все документы слоёв стоят в `status: draft`, а описанное поведение помечено как **целевое**.
`research/research-architecture.md` — исключение: он `active`, потому что его факты проверены по
артефактам, а не по замыслу, и у каждого указано, где именно.

Первый же коммит кода, разошедшийся с документом, правит **документ**, а не оставляет расхождение.

## Соглашения

- `id` во frontmatter = имя файла.
- **Главный потребитель — Claude Code.** Каждый документ даёт якоря кода: путь к файлу, а не
  пересказ его содержимого. Путь остаётся верным, копия протухает.
- Один документ = одна сущность. Фича, затрагивающая оба сервиса, — **один** файл со списком
  `involved_services`.
- Числа, статусы и тексты ошибок в BDD — только проверенные по коду; пока кода нет, они помечены
  как целевые.
- Гипотезы называются гипотезами, и у каждой есть **адрес проверки** («проверить в M2»).
  Документ, который не отличает проверенное от предполагаемого, вреднее отсутствия документа.
- Язык документации — русский; идентификаторы, URL, заголовки HTTP — как в коде. Код, комментарии,
  KDoc, имена тестов, сообщения исключений и коммиты — английские (`CONTRIBUTING.md`).
- Шаблоны для новых документов — `templates/`.
