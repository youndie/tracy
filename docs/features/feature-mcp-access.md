# Доступ кодового агента к логам через MCP

> `status: active` — написано в M6 и проверено на живом сокете. Открытыми остаются два пункта, и
> оба честнее назвать, чем закрыть: **M-66** — замер ложных срабатываний скрина сделан на слабом
> корпусе (0 из 23 600, но различных форм сообщений там ~704 и прозы нет), **M-67** — настоящего
> MCP-клиента к серверу ещё не подключали, это идёт вместе с выкаткой.

## 1. Суть

Основной путь чтения логов tracy — **MCP**, а не веб-интерфейс (research §Р9). Агент, разбирающий
баг, получает не «ссылку на дашборд», а инструменты: найти записи, взять ленту трассы, посмотреть
частотные ошибки, дочитать окрестности конкретной записи.

Это меняет требования к API по сравнению с человеческим: ответ должен помещаться в контекст. Пять
тысяч строк лога — не «подробный ответ», а испорченная сессия. Поэтому каждый инструмент
агрегирует или ограничивает выдачу и **явно сообщает об усечении**.

Контракт инструментов — [mcp-tools](../api/mcp-tools.md).

## 2. Бизнес-ограничения

* Инструментов — **5–6**, все `readOnly`. Коридор 1–10; модели деградируют после 30–40
  (katcher §5).
* **MCP выключен по умолчанию**: не задан `TRACY_MCP_TOKEN` — не устанавливается ни транспорт, ни
  перехватчик, ни ingress-маршрут. Отсутствие конфигурации даёт закрытое состояние, не открытое.
* Аутентификация MCP **не переиспользует** доверие к заголовкам reverse proxy: тот принимает любую
  заявленную личность, что допустимо для браузера и недопустимо для машинного эндпоинта.
* **Недоверенный текст никогда не отдаётся в первом ответе.** Первый вызов возвращает
  структурированные факты; свободный текст — вторым вызовом (§3).
* Находки скрина **не цитируют** удержанный текст: их читает тот самый агент, которого мы защищаем.
* Удержание записи не прячет её: запись остаётся в выдаче с признаком `withheld` и перечнем
  сработавших правил. Тихо выкинуть подозрительную запись — худший из вариантов.

## 3. Как это работает

Модель угроз — research §1.9 (Agentjacking, 85% успешных эксплуатаций в контролируемом
тестировании; авторы прямо говорят, что это ограничение моделей, а не конфигурации).

**Первый контур — разделение на записи.** Главное отличие tracy от MCP-адаптеров над Loki и Sentry:
доверенное и недоверенное разделены в момент записи
([feature-structured-logging](feature-structured-logging.md)), а не угадываются при чтении.

| Часть записи | Кто автор | Как отдаётся |
|---|---|---|
| `message` при `untrusted_message = 0` | разработчик сервиса | как есть |
| `fields` (значения) | во многом внешний вызывающий | экранируются, помечаются происхождением, вторая фаза |
| `message` при `untrusted_message = 1` | смешанное | как поле |

**Второй контур — статический скрин** (по образцу `CrashTrust` в katcher): язык, обращённый к
читателю; shell-вызовы; упоминания секретов; невидимые символы (zero-width, bidi-override).
Применяется к недоверенным частям, **не** к шаблонам разработчика — иначе ложные срабатывания на
обычной прозе логов (research риск 4).

**Третий контур — две фазы.** Порядок принципиален: агента, уже прочитавшего инъекцию, бессмысленно
спрашивать, инъекция ли это.

1. `search_logs` / `get_trace` отдают структуру: время, сервис, уровень, логгер, шаблон, `trace_id`,
   ключи полей и их типы — но не значения свободного текста;
2. `get_entry_content` отдаёт значения — и требует от агента опровержимого отчёта о том, что он
   проверил. Опровержимого: сервер знает настоящие данные и отказывает, если отчёт с ними не
   сходится.

Урок katcher, который сюда переносится дословно: **правило гейта не должно наказывать за
честность**. Первая версия требовала, чтобы все заявленные фреймы резолвились в репозитории, —
и блокировала агента, честно пометившего библиотечные фреймы, пропуская того, кто отчитался
скупее. Для tracy аналогичная ловушка: требовать, чтобы агент «объяснил» каждую запись.

## 5. Сценарии

### Сценарий: без токена эндпоинт не существует *(целевое)*
* **Дано:** `TRACY_MCP_TOKEN` не задан.
* **Когда:** выполняется `POST /mcp`.
* **Тогда:** `404` — транспорт не установлен вовсе; в чарте нет ни секрета, ни маршрута.

### Сценарий: неверный токен → 401, а не страница логина *(целевое)*
* **Дано:** токен задан.
* **Когда:** приходит запрос с неверным `Authorization`.
* **Тогда:** `401` с телом ошибки. Редирект на `/login` применяется только к запросам с
  `Accept: text/html` (katcher §6, находка 3).

### Сценарий: подсаженная инструкция в значении поля удерживается *(целевое)*
* **Дано:** внешний вызывающий передал в заголовке текст, обращённый к агенту, и он попал в
  `fields`.
* **Когда:** агент вызывает `search_logs`.
* **Тогда:** запись видна, значение поля удержано, возвращены сработавшие правила без цитирования
  payload'а.

### Сценарий: `get_trace` не взрывает контекст *(целевое)*
* **Дано:** трасса из 40 000 записей.
* **Когда:** агент вызывает `get_trace`.
* **Тогда:** возвращается не более `limit` записей, сгруппированных по сервисам, с числом
  оставшихся и подсказкой, как сузить.

### Сценарий: чужой `Host` отвергается *(целевое)*
* **Дано:** `TRACY_MCP_ALLOWED_HOSTS` содержит хост релиза.
* **Когда:** приходит запрос с другим `Host`.
* **Тогда:** `Invalid Host` — защита транспорта от DNS rebinding не отключается
  (katcher §7, находка 2).

## 6. Что не входит в скоуп

* **OAuth 2.1 из спеки MCP** (RFC 9728, RFC 8707). Для single-tenant self-hosted статический
  токен — прагматичный выбор, но это **отклонение от спеки, а не соответствие ей**.
* **Разграничение доступа по сервисам.** Один токен на сервер: любой держатель видит все логи.
  Для логов это весит больше, чем для крашей (research §Р11, открытый вопрос 1).
* **Инструменты записи.** Всё `readOnly`; ничего в базе агент менять не может.

## 7. Известные особенности

* **Баг `protocolVersion` в MCP Kotlin SDK 0.15.0.** Поле имеет значение по умолчанию,
  kotlinx.serialization дефолты не пишет, при фолбэке поле исчезает из ответа, и **ломается любой
  актуальный клиент**. Обход katcher — подмена версии в **запросе** на `2025-06-18`. Шим
  временный; убрать, когда SDK пометит поле `@EncodeDefault`.
* **`mcpStatelessStreamableHttp` — расширение `Application`, а не `Route`**, и сам ставит роутинг.
  Вложить в `authenticate { }` нельзя, авторизация — перехватчиком пайплайна.
* **`allowedHosts` по умолчанию — только localhost.** Класс ошибок «работает только в развёрнутом
  виде» здесь существует и тестами не закрывается: локально Host всегда localhost. Разворачивать
  раньше, чем кажется нужным.
* **Замер ложных срабатываний скрина у katcher — 0 из 134 групп**, но он измеряет только ложные
  *срабатывания*. Про ложные *пропуски* не говорит ничего: настоящих атак в базе нет. Для tracy
  свой замер обязателен — тексты здесь на два порядка обильнее и разнороднее.
