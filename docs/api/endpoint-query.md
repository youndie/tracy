# API: чтение логов

> `status: active` — написано и покрыто тестами; на живом контуре не крутилось (M-74).
> Курсор из списка параметров убран: его в коде нет и не будет, сужать вместо листания — решение.
> С M-101 маршруты описаны типами (`@Resource`), а не строками, и параметры ниже — это поля
> классов в `query/QueryResources.kt`. Поэтому расхождение вроде того же `cursor` теперь ловится
> компилятором, а не ревизией документов через несколько вех. Заодно переименован фильтр ошибок у
> `/api/spans`: было `error=true`, стало `onlyErrors` — MCP-инструмент всегда звал его так, и два
> имени у одного фильтра были ровно тем расхождением, против которого типы и заводятся.
> Тот же набор данных отдаётся агенту через
> [mcp-tools](mcp-tools.md); HTTP-слой существует для человека, для `curl` при отладке и как
> основа будущего UI. **Формы ответов общие, защита — разная**: HTTP отдаёт данные как есть,
> MCP пропускает их через скрин и две фазы (research §1.9).

## Маршруты — все, без исключений

| Метод и путь | Auth-tier | Назначение |
|---|---|---|
| `POST /ingest` | `X-Tracy-Key` | приём батча, [protocol-ingest](protocol-ingest.md) |
| `GET /api/services` | заголовки reverse proxy | сервисы, инстансы, последняя активность, **произведено и сохранено байт** по уровням за окно, число ссылок на ключ |
| `GET /api/logs` | заголовки reverse proxy | поиск: `service`, `instance`, `level`, `since`, `until`, `q`, `templateId`, `exceptionClass`, `traceId`, `entityKey`+`entityValue`, `limit` |
| `GET /api/spans` | заголовки reverse proxy | поиск по спанам: `service`, `name`, `minDurationMs`, `onlyErrors`, `since`, `until`, `limit` |
| `GET /api/entities/{key}/{value}` | заголовки reverse proxy | хронология сущности по всем сервисам и трассам |
| `GET /api/entities/{key}/top` | заголовки reverse proxy | агрегация по значению: `since`, `until`, `limit` |
| `POST /api/entities/{key}/unsuppress` | заголовки reverse proxy | снять предохранитель с ключа; идемпотентно |
| `GET /api/traces/{traceId}` | заголовки reverse proxy | **дерево спанов + вписанные записи логов** по всем сервисам |
| `GET /api/templates` | заголовки reverse proxy | частотные шаблоны: `service`, `since`, `until`, `level`, `release`, `step`, `limit`. `step` даёт **ряд по времени**, `release` — разрез по выкату |
| `GET /health` | нет | живость + состояние ретенции |
| `POST /mcp` | `Authorization: Bearer` | MCP, [mcp-tools](mcp-tools.md); маршрута нет, если токен не задан |

**Auth-tier «заголовки reverse proxy»** означает буквально то же, что в metrik и katcher: сервер
доверяет `X-Auth-Request-User` / `X-Auth-Request-Email`, своего логина не имеет, без заголовков
отвечает `401`. Следствие, которое надо писать в README крупно: **tracy без прокси перед
`/api/**` ставить нельзя.**

`/ingest` и `/mcp` намеренно **не** используют этот механизм: прокси принимает любую заявленную
личность, что допустимо для браузера и является подарком для машинного эндпоинта.

## Что означает выдача — и чего она не означает

Три места, где ответ легко прочитать сильнее, чем он есть:

* **Запрос по окну времени возвращает не «все логи».** Возвращаются все записи `WARN` и выше,
  ссылки на сущности — и `sampleRate` доля тел `INFO` вместе со спанами их трасс (research §Р7).
  Ответ несёт `sampleRate` окна явным полем, чтобы это было видно, а не выводилось.
* **`/api/spans` — тоже выборка.** «Сколько всего было медленных запросов» — вопрос к metrik;
  здесь лежат те, чьи трассы сохранились.
* **`q` ищет по шаблонам, а не по телам** (research §Р5). Подставленное значение через него не
  найдётся — для значений `entityKey`/`entityValue`.
* **Числа в `/api/templates` — точные**, потому что берутся из счётчиков агента, а не из
  сохранённых строк (research §Р13). Это единственная выдача, которую можно умножать и сравнивать.
* **Ссылка на сущность без тела записи — это данные.** `entry_id = null` означает «сущность здесь
  трогали, тело не сохранено», а не «ничего не было».
* **Подавленный ключ создаёт временную границу, и она в ответе.** Выдача по такому ключу несёт
  `suppressedSince`: до этого момента история полная, после — её нет. Отдавать пустоту как
  «обращений не было» нельзя — это ложноотрицательный ответ (research §Р15).

## Общие правила выдачи

* У каждой коллекции **жёсткий потолок** `limit` с серверным максимумом. Усечение сообщается
  явно: `{"items":[…],"truncated":true,"remaining":11800}`. Молча обрезанная выдача читается как
  «это всё».
* Пагинация — курсором по `(ts, n)`, не `offset`: логи дописываются во время листания.
* Время — epoch ms. В ответе присутствуют и `t` (часы источника), и `receivedAt` (часы сервера);
  расхождение больше 5 секунд помечает инстанс (research риск 6).

## Ошибки

| Условие | Статус | Тело |
|---|---|---|
| нет заголовков прокси на `/api/**` | `401` | `{"error":"unauthorized"}` |
| `limit` больше максимума | `400` | `{"error":"limit exceeds maximum"}` |
| неизвестный `traceId` | `200` | пустое дерево — не `404`: отсутствие данных это ответ, а не ошибка. Отличить «трассы не было» от «трасса отброшена семплированием» по этому ответу нельзя, и это надо помнить (research §Р7) |
| диапазон `since`/`until` вывернут | `400` | `{"error":"since must be before until"}` |
| `entityKey` не индексируется | `400` | `{"error":"key is not indexed","indexed":[…]}` — **не** пустой результат: пустой читается как «такого не было» |
| `unsuppress` по неподавленному ключу | `200` | идемпотентность: повтор не ошибка |
| `unsuppress` по неизвестному ключу | `404` | `{"error":"unknown key"}` |

## Форма ответа `GET /api/traces/{traceId}`

Дерево, а не плоский список: узел — спан, у него дети-спаны и записи логов, сделанные внутри него.
Поля узла — по [protocol-ingest](protocol-ingest.md), плюс вычисляемые сервером:

| Поле | Смысл |
|---|---|
| `unattributedMs` | длительность спана минус сумма известных детей |
| `noRemoteData` | у клиентского спана нет ответной серверной стороны — **потерянное звено**, а не отсутствие вызова |
| `unterminated` | спан не закрыт: сброшен при штатном завершении процесса |
| `orphan` | родитель не доехал; узел подвешен к корню, а не выброшен |

Записи логов без `span_id` (сделанные из не-suspend кода, research §1.3) собираются в отдельный
список уровня трассы — терять их из-за отсутствия родителя нельзя.

## Особенности

* **Редакция видна.** Поле `r` записи (protocol-ingest) перечисляет отредактированные имена, и API
  их отдаёт: иначе замаскированное значение неотличимо от пустого.
* **`GET /api/logs` без `service`** допустим и дёшев в узком окне: суточные партиции сами режут
  диапазон. Дорог он на длинном диапазоне — `UNION ALL` по тридцати партициям; серверный максимум
  `limit` для такого запроса ниже.
* **`StatusPages` не должен превращать `401` в редирект на `/login` для не-браузерных клиентов** —
  ровно эта ошибка ломала MCP в katcher (research §1.8).
